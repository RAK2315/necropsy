# Design Document

## Overview

Two pieces, both outside the engine:

- `tools/adversary.py`: the blind generator and the measurement. `python -m tools.adversary` writes `tools/adversary_counts.json`.
- `tests/test_gate_perturbation.py`: the perturbation test. `tests/test_adversary_tool.py` tests the instrument.

Neither changes `necropsy/`.

## Finding

**Closure alone admits about 2% of arbitrary layouts, and that is expected.**

The gate checks that `data_end − header_size` equals `row_stride × height` (or that the RLE decoder fills exactly that many bytes and consumes the whole region). `header_size` is an input. For almost any width, height, bit depth and row alignment there is a header size that makes the arithmetic fit, so the gate accepts it.

Example, `mystery_b` (955 bytes): width 1, height 1, bit depth 1, header size 185, no encoding, row alignment 1. The data region is 1 byte, then the 769-byte `pcx_palette_256` trailer matches, and 185 + 1 + 769 = 955. It closes. No file declares a 185-byte header.

The engine never reaches such a layout. A header size comes from one of two places: a probe reading a declared field (PCX 128, TGA 18 plus ID and colour-map bytes, PBM end of the text header, TIFF StripOffsets), or Generic Search's defined axes. The blind generator invents header sizes, so it samples a space the engine cannot reach. Its closures are not reachable defects.

Decision Record 4 of the engine spec was a different case. There 224 of 1,521 width/height pairs below 40 closed on `mystery_b`, including the naive 7×7, under the header size the probe supplied (128). Only width and height varied, so those layouts were reachable. They closed because the decoder did not require full consumption, and the full-consumption rule fixed it.

**Conclusion: the gate's strength comes from the hypothesis source, not from closure in isolation.** Closure turns a hypothesis into a checked one. The probes and the Generic Search axes decide which hypotheses exist at all. The perturbation test below measures that second part.

## Axes

The generator is `generate_layouts(size: int)`. Origin is the trailer-registry origin (`generic`, `pcx`, `tga`, `pbm`); only `generic` and `pcx`/`tga` match trailers.

| Axis | Width, height | Bit depth | Alignment | Encoding | Header size | Other |
|---|---|---|---|---|---|---|
| 1. grid | 1..24 each | 1, 2, 4, 8, 16, 24, 32 | 1, 2, 4 | none, rle_pcx | constants `0, 7, 8, 12, 18, 26, 40, 54, 86, 96, 128`, plus exact-fill headers `size − stride×height − t + d` for trailer length `t ∈ {0, 26, 769}`, `d ∈ {−1, 0, 1}` | origin `generic` |
| 2. header sweep | 1..6 each | as above | as above | as above | every value `0..min(size+1, 160)` not covered by axis 1 | origin `generic` |
| 3. origin | 1..8 each | as above | as above | as above | constants | origins `pcx`, `tga`, `pbm` |
| 4. strips | one side `1..3`, the other `((size − header) × 8) // depth + d`, `d ∈ −2..2`, kept only above 24 | as above | as above | as above | constants | origin `generic` |
| 5. declared end | 1..8 each | as above | as above | as above | constants | `data_end = size − b`, `b ∈ {1, 2, 3, 4, 8, 26, 769}`; never `size` |

Header constants and exact-fill headers use format knowledge of the test author (PCX 128, TGA 18, and so on) and the file size. They do not use the engine's result. Axis 5 never produces `data_end == size`, because that only re-spells "no declared end".

### Exclusion and the respelled rule

`run_adversary(data, result)` excludes generated layouts whose `hypothesis_key` is a reported candidate's key. A layout that closes and was not excluded is **respelled** when `(width, height, bit_depth, header_size, row_stride, encoding, data_start, data_end)` equals the same tuple for a reported candidate. A respelled layout is the same layout, so it is not a wrong layout that closed. It is reported apart (`respelled_candidate`) so the rule stays checkable and nothing is hidden inside either count.

## Perturbation

For each Sample a probe handles, `tests/test_gate_perturbation.py` replaces one declared dimension and re-runs `Engine().run`.

### Offsets and formats

| Format | Samples | Width field | Height field |
|---|---|---|---|
| PCX | mystery_b, mystery_i, mystery_h, external_a | xmax, offset `0x08`, `<H` | ymax, offset `0x0A`, `<H` |
| TGA | mystery_c, external_b | offset `0x0C`, `<H` | offset `0x0E`, `<H` |
| TIFF (big-endian) | mystery_e | value field of the tag 256 entry, offset 18, `>H` | value field of the tag 257 entry, offset 30, `>H` |
| PBM | mystery_a | one ASCII digit at offset 3 | one ASCII digit at offset 5 |

The TIFF offsets are found by an IFD walk written separately from the engine's probe. `test_table_offsets_hold_the_declared_values` asserts that each offset holds the value in the table (PCX `7, 7` for `mystery_b`, `63, 47` for `external_a`, TGA `64, 48` for `external_b`, and so on).

### The claim and what "tracks" means

After a perturbation to value `v`, the result must be FAILED, or every candidate must have, on the perturbed axis, the dimension `v`, or `v + 1` for PCX (PCX bounds are inclusive and the engine's `inclusive_bounds` revision adds one). No candidate may have a `hypothesis_key` equal to a key of the unperturbed result.

This is not tautological. The generator in the finding above draws layouts from outside the engine. The perturbation draws files from inside its input space: real headers with one field changed. It tests the probe-to-gate path where the engine actually operates.
